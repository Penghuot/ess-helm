2. Handling key.pem on Railway
You have two options:

Option A: Environment variable  
Add a variable MAS_SIGNING_KEY in Railway, paste the PEM contents directly:

Code
-----BEGIN EC PRIVATE KEY-----
...
-----END EC PRIVATE KEY-----
Your entrypoint script will inject it into config.yaml.

Option B: File mount (cleaner)  
Commit key.pem to your repo (or upload to Railway’s file storage).
Mount it into the container at /app/key.pem.
In your entrypoint, set:

bash
MAS_SIGNING_KEY="$(cat /app/key.pem)"
This avoids multi‑line env var headaches.

3. Automation Flow
Locally: run with docker run --env-file .env ....

On Railway: paste the same .env values into the Environment tab.

Entrypoint scripts: render configs with placeholders ({{VAR}}).

Result: Synapse and MAS auto‑know each other every rebuild.

✅ With this setup, you don’t touch configs. Railway injects env vars, entrypoints render YAML, and both services stay in sync.
